## 本次会话修复的缺陷（冒烟测试发现）

1. `ledger:memory-import` 不幂等：payload 含 `throughMemorySeq`（每次导入都前进），
   导致同 eventId + 不同 payload，id-retry 判冲突 → `failed`。改为写入前 `getById` 预探测 → `skipped_imported`。
2. `ledger:memory-import --dry-run` 有副作用：制品 `put` 排在 dry-run 分支之前。已把制品写入移到 append 之前。
3. `runMemoryImport` 丢弃 `options.tapeStore`（未透传给 `importMemoryBranch`）。
4. Phase 1 遗留测试隔离缺陷：`fact-ledger-stores.test.ts` 用 `sha256CanonicalJson(null)` 作内容，
   制品按内容全局去重 → 该常量内容全库只能 append 一次 → **disposable PG 集成测试不可重跑**
   （首轮 54/54，次轮 51/54）。已拆分为"nonce 化内容测去重" + "仅断言 inlineJson===null 测 null 保留"。

## 运维要点（下次别踩）

- 三个 ledger CLI 走 `getPrisma()`，必须同时设置 `DATABASE_URL` 与 `DIRECT_URL`
  （`src/db/prisma-env.ts` 的 `ensurePrismaUrls()` 两个都要求），与 `FACT_LEDGER_TEST_DATABASE_URL` 无关。
- 集成测试同样需要 `DATABASE_URL` / `DIRECT_URL`（部分代码路径内部用全局 `getPrisma()`）。
- `prisma-cli.ts` 会 spawn `prisma`，需 `PATH="$PWD/packages/server/node_modules/.bin:$PATH"`，否则 ENOENT。
- fact ledger 表（`artifact_revisions`、`conversation_events` 等）有不可变触发器，DELETE/UPDATE 会被拒绝。
