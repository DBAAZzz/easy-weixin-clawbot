# Dumi 组件详情页视觉统一设计

## 背景

`packages/ui` 的文档首页已经形成清晰的品牌语言：浅色纸张背景、克制留白、细边界、局部暖色光晕和 Geist 字体。现有组件详情页仍保留传统 dumi 的大内容卡片、分离式侧栏、默认 Previewer 和厚重 API 表格，与首页不属于同一套视觉系统。

本设计只改造 dumi 主体和组件文档的呈现层，不修改 `@clawbot/ui` 组件实现，也不改变组件 Markdown 的事实源角色。

## 目标

1. 让所有组件详情页与文档首页使用同一套设计语言。
2. PC 端优先，在保留组件查阅效率的同时提升品牌感。
3. 保留 dumi 的路由、Markdown、Demo、API 元数据、搜索和 Playground 能力。
4. 保持文档公开、`@clawbot/ui` 包继续仅供仓库内部使用。
5. 新增组件文档后自动继承详情页设计，不要求逐页手工适配。

## 非目标

- 不修改 Button、Dialog 等组件本身的视觉实现。
- 不重新设计已经确认的文档首页。
- 不引入暗色模式。
- 不公开发布 `@clawbot/ui` 包，也不添加 NPM 跳转。
- 不重写 dumi 的 Markdown、Demo 或 API 数据生成链路。

## 设计方向

采用自定义 dumi Theme Slots，而不是只覆盖 CSS 或完全重写文档渲染器。

需要重组的呈现单元包括：

- `DocLayout`：组件页总体布局和响应式切换。
- `Content`：组件标题、描述、导入代码和 Markdown 正文。
- `Previewer`：演示舞台、参数控制台、源码和独立预览入口。
- `Sidebar`：组件分组与当前组件导航。
- `Toc`：页内锚点导航。
- 全局文档样式：字体、颜色、间距、横线、表格和代码样式。

dumi 继续负责内容与数据，主题层只负责组织和视觉。

## PC 页面骨架

PC 端采用编辑式三栏，但三栏不是三个独立面板，而是同一张纸上的三个逻辑区域：

1. 左侧组件导航。
2. 中间组件正文。
3. 右侧页内目录。

Header 之外不使用大面积白色圆角内容卡片，不给左右导航设置独立底色，也不使用贯穿全高的竖向分割线。三个区域共享同一个浅色页面背景，通过留白、排版和局部状态建立层级。

### 左侧组件导航

- 保留组件分类和完整组件列表，PC 端 Sticky。
- 不显示菜单右侧分割线。
- 不使用独立侧栏背景。
- 分组标题使用小字号中性文字。
- 普通组件项只显示文本；当前组件使用深色圆角胶囊。
- 分类、组件名称和激活状态继续来自 dumi sidebar 数据。

### 中间正文

正文依次包含：

1. 组件标题区。
2. Playground。
3. 使用说明与其他 Markdown 内容。
4. API Contract。

组件标题区合并现有 Markdown 标题和 API Header，页面只保留一个 H1。标题区包括：

- 英文组件名称。
- 一句话中文描述。
- `import { Component } from '@clawbot/ui'` 代码。
- 复制导入代码操作。

不显示 NPM 链接，因为组件包保持私有。

### 右侧页内目录

- PC 端 Sticky。
- 与正文共享背景和内容边界，不形成独立右栏面板。
- 不使用贯穿全高的分割线。
- 只在目录内部保留一条短而淡的锚点线。
- 当前章节使用更深文字和短活动指示线。
- 内容来自 dumi route TOC，不复制 Markdown 数据。

## 视觉语言

### 背景与氛围

- 固定浅色模式。
- 页面使用温和的纸张底色，避免纯白和冷灰。
- 不使用横向或纵向网格背景。
- 暖色光晕只出现在组件标题区和 Playground 舞台，透明度低且边缘模糊。
- API、长正文和左右导航保持安静，不扩散暖色光晕。
- 内容层级主要依靠留白、字体和细横线。

### 字体层级

字体资源使用项目现有的本地 Geist Variable 与 Noto Sans SC Variable，不依赖 CDN。

最终 PC 字号与字重基准：

| 元素 | 字号 | 字重 | 字体 |
| --- | ---: | ---: | --- |
| 英文组件名称 | 46px | 700 | Geist Variable |
| 英文章节标题 | 28px | 700 | Geist Variable |
| 描述与正文 | 16px | 400 | Geist / Noto Sans SC |
| 左侧菜单项 | 14px | 400；激活项 600 | Geist / Noto Sans SC |
| 页内目录 | 14px | 400；激活项 600 | Geist Variable |
| Prop 名称 | 14px | 400 | Geist Variable |
| 导航与操作 | 12–14px | 500 | Geist / Noto Sans SC |
| 类型和值 | 10–12px | 400 | 等宽字体栈 |

组件名称、章节标题和 Prop 名称不再使用 Geist Thin。类型联合、默认值和代码片段保留等宽字体，避免失去代码辨识度。

## Playground

采用“舞台 + 横向控制台”结构。

### 舞台

- 上方细标题栏显示 Demo 名称和视口入口。
- 舞台背景无网格，使用浅色表面和局部暖色光晕。
- Demo 组件位于视觉中心。
- 舞台保持足够留白，不使用厚阴影或大圆角。

### 横向控制台

- 常用参数在舞台下方横向排列。
- 参数标签、输入控件和开关保持紧凑。
- 参数继续由 dumi Playground/Tweaks 数据驱动，不建立新的状态源。
- 源码、全屏或独立预览等次级动作进入最下方的细操作栏。

现有 `center`、`nopadding` 和 `pure` Previewer 语义继续支持：

- `center` 只改变舞台内容对齐。
- `nopadding` 移除舞台内边距，但保留 Previewer 外壳。
- `pure` 移除完整 Previewer 外壳和元信息。

参数过多时，PC 控制台允许自动换行；不将所有参数强行压进单行。

## API Contract

采用编辑式横向表格：

- 不使用厚重外框和完整单元格边框。
- 只使用细横线分隔表头与属性行。
- Prop 名使用 Geist 14px/400。
- 类型和默认值使用等宽字体及低对比浅色底。
- 描述保持普通正文样式。
- 多个 API 分组继续使用 Markdown H3 作为分组标题。

PC 端优先保证横向扫描效率。窄屏时表格允许局部横向滚动，不能压缩到不可读，也不改变 Markdown 表格语义。

## 移动端降级

移动端不是主设计目标，但需要可靠可用：

- 左右固定导航不保留为桌面三栏。
- Header 下方增加组件上下文条，用于显示当前组件和打开组件目录。
- 页内目录改为可横向滚动的锚点条。
- 正文、Playground 控制台和 API 表格按可用宽度换行或局部滚动。
- 不使用固定底部导航，也不新增第二套移动应用式交互。

## 数据流与边界

### 页面元数据

- `useRouteMeta()` 提供组件标题、描述、atomId 和 TOC。
- `useSidebarData()` 或 `useFullSidebarData()` 提供组件分类和当前路由。
- Markdown 仍负责正文、Demo 声明和 API 表格内容。

### 标题去重

主题层根据 `frontmatter.atomId` 识别组件详情页，并由 `Content` 统一渲染组件标题区。Markdown 中原有的第一个 H1 不得再次显示，最终 DOM 只包含一个页面 H1。

### 缺失数据降级

- 缺少 `atomId`：按普通文档页渲染，不展示组件导入代码。
- 缺少 description：省略描述区域，不填充占位文案。
- 缺少 sidebar 分组：组件进入“其他”分组，并在开发环境输出警告。
- TOC 为空：不渲染右侧目录，同时释放对应空间。
- Playground 参数为空：只显示舞台和底部动作栏。

不静默吞掉主题渲染异常；开发环境保留明确警告，生产构建使用可用内容降级。

## 可访问性

- 页面只保留一个 H1，章节层级从 H2 开始。
- 当前组件导航和当前 TOC 项使用 `aria-current`。
- 复制、打开源码、全屏和移动菜单都有可读标签。
- 键盘焦点使用高对比可见样式。
- 暖色光晕为装饰元素，不参与可访问树。
- 动画遵循 `prefers-reduced-motion`。
- 字体缩放到 200% 时仍能访问导航、Playground 和 API 内容。

## 文件边界建议

为避免主题文件继续膨胀，按职责拆分：

- `layouts/DocLayout`：布局和响应式结构。
- `slots/Content`：标题区与正文包装。
- `builtins/Previewer`：舞台和控制台包装。
- `slots/Sidebar`：组件导航语义。
- `slots/Toc`：页内目录语义。
- 每个单元拥有相邻样式文件；全局 `style.css` 只保留 token、字体和跨单元基础样式。

不进行与本次目标无关的组件源码重构。

## 验证方案

### 自动检查

- `pnpm -F @clawbot/ui exec tsc --noEmit`
- `pnpm -F @clawbot/ui lint`
- 对本次变更文件运行 oxfmt。
- `pnpm -F @clawbot/ui docs:build`
- `git diff --check`

### 页面检查

至少验证：

- Button：基础组件与典型 Playground。
- Dialog：长 API 与多个 API 分组。
- AdminCard：业务组件分组。
- Icons：非标准 Demo 内容。
- 一个没有 TOC 或参数控制的简单组件页面。

浏览器检查尺寸：

- 1440px PC 主视图。
- 1280px 较窄 PC。
- 1024px 平板降级点。
- 390px 移动端。

### 交互检查

- 左侧组件导航切换。
- TOC 锚点和滚动激活状态。
- 复制导入代码。
- Playground 参数修改。
- 源码和独立预览入口。
- 移动端组件目录和横向锚点条。
- 键盘导航和焦点可见性。

## 验收标准

1. PC 组件详情页与首页在字体、背景、留白、边界和暖色氛围上属于同一视觉系统。
2. 页面没有网格背景、大白内容卡片或左右栏贯穿全高的分割线。
3. 左侧菜单和右侧 TOC 自然融入同一页面背景。
4. 组件名、章节标题、正文、导航和 Prop 使用本文确定的字号与字重。
5. Playground 使用舞台加横向控制台，并保留现有交互能力。
6. API 表格使用细横线的编辑式呈现，长 API 仍可快速扫描。
7. 所有现有组件 Markdown 无需逐页重写即可获得新主题。
8. dumi 生产构建、类型检查和 lint 通过。
9. 文档可以公开部署，`@clawbot/ui` 继续保持私有。
